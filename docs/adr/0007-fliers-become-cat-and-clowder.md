# Fliers become a Cat and a Clowder, never a new entity kind

A captured missing-cat flier (issue #26) is stored as two existing entities: a Cat that is a Stray with no sighting positions, and the owner's Clowder (contact/address, Status "owner") which the Cat's membership history shows it leaving on the missing-since date. There is no flier entity and no "missing" flag — missing-ness is derived from the history, exactly as Stray and Adoption are derived states, so photos, Fields, sync, and Merge all apply unchanged and the flier's provenance stays reconstructable from append-only history (ADR-0001) after a Merge with a found cat.

A dedicated flier/missing-cat entity was rejected: it would duplicate photo, field, sync, and merge machinery for a record that is conceptually just a cat plus a place it went missing from. A pseudo-Clowder "missing" holding all missing cats was rejected because a Clowder is one place with an address and a responsible person. The price accepted: flier capture spawns real one-cat Clowders of strangers' homes (filterable via Status "owner"), and positions need a kind (sighting | flier) so a flier's posting place is never mistaken for a sighting.
