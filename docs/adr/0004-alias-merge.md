# Duplicates merge by alias, never by copying

Cats, Clowders, and Field definitions all get duplicated when several people register the same real thing. Merge is one mechanism for all three: the user picks the survivor, and a single `$mergedInto` entry is appended to the loser — no entry is copied or rewritten. Reads resolve the alias (chains followed, cycles refused at merge time): Cat and Clowder reads unite the alias group's entries; membership pointing at a merged Clowder resolves to the survivor; values stored under a merged Field's key read as the survivor's field; Field-definition properties come from the survivor only. Survivor-wins for Cats and Clowders is achieved by re-asserting the survivor's current values as fresh entries at merge time, so the loser's newer entries cannot override them, while loser values still fill fields the survivor never had. Field merges are restricted to equal types.

Copy-based merge was rejected: copied entries fake authorship or dates, and a device that was offline during the merge would re-sync the loser's original entries into a record that no longer exists — the alias absorbs exactly this case, because late-arriving entries against the loser resolve to the survivor on every read. The price is alias resolution in every read path, which is negligible at this data size. Merges are irreversible by design (CONTEXT.md: Merge).
